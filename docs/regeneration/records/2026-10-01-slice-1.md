## Compatibility findings (documented, NOT fixed — runtime out of campaign scope)

1. **CRLF SSE framing (SDK, latent bug)**: `sdk/src/sse.ts` `parseSSEStream`
   splits only on `"\n\n"`; a spec-legal CRLF-framed event-stream body
   (`data: {...}\r\n\r\n`) yields **zero events** — hermetically reproduced.
   cortex-app emits LF-terminated frames (verified in `backend/app/main.py`
   stream emitters), so latent against conformant third-party proxies only.
   Reproduction: `data: {"content":"a"}\r\n\r\n` into `parseSSEStream` → no
   events. Fix belongs to the SDK runtime owner; current LF contract asserted
   in `sdk/test/contract.test.ts` with a comment pointing here.
2. **MCP version-constant drift**: `mcp-server/src/index.ts` advertises MCP
   `version: "0.2.0"` while `mcp-server/package.json` is `0.3.1` —
   distribution-facing; reconcile with the runtime owner.
3. **Stale committed lockfile**: `package-lock.json` recorded workspace sdk
   version `0.1.2` vs `sdk/package.json` `0.1.3`; `npm install` synced it
   during the campaign (left unstaged as a finding); `npm ci --dry-run` now
   consistent. Release process should regenerate the lock on version bumps.
4. Testing note: a naive mock fetch ignores `init.signal`, so timeout aborts
   cannot be exercised through it — the timeout gate uses a real loopback
   socket instead.
